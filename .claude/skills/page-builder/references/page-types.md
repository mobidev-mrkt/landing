# Page type registry

Which page types a B2B service website needs, what each one is for, and which Kit builds it.

`Kit ✓` = a full Kit ships with this skill. `nearest` = no dedicated Kit yet; build from the named
Kit and say so in the handover.

## Bottom of funnel — pages that close

| Type | Job | Kit |
|---|---|---|
| **Service page** | One service in full: who it is for, what is included, process, price, proof | Service Page Kit ✓ |
| **Industry page** | The same service in one vertical's language, standards and cycles | Industry Page Kit ✓ |
| **Case study** | One project, one number, one narrative | Case Study Kit ✓ |
| **Landing page** | One campaign, one offer, one action, no navigation | Service Page Kit ✓ (strip nav, single action) |
| **Comparison** | Approach A vs approach B for a buyer mid-decision | Blog Page Kit ✓ (comparison table mandatory) |
| **Alternatives** | Positioned against a well-known option the buyer already knows | Blog Page Kit ✓ |
| **Pricing** | How you charge, what moves the number, what a typical engagement costs | nearest: Service Page Kit |
| **About / team** | Who does the work and why they can be trusted | nearest: Service Page Kit |

## Middle of funnel — pages that qualify

| Type | Job | Kit |
|---|---|---|
| **How-to guide** | Teach one concrete task end to end | Blog Page Kit ✓ |
| **Checklist** | Let the reader verify their own state | Blog Page Kit ✓ |
| **Best-of roundup** | Curate the options in a category | Blog Page Kit ✓ |
| **Review** | Judge one tool or approach honestly, including where it fails | Blog Page Kit ✓ |
| **Template** | A reusable artifact the reader adapts | nearest: Blog Page Kit |
| **Free tool** | A calculator or generator that returns a result | no Kit — product work |

## Top of funnel — pages that build authority

| Type | Job | Kit |
|---|---|---|
| **Pillar / hub** | The comprehensive page a cluster hangs off | Blog Page Kit ✓ (link map mandatory) |
| **Ultimate guide** | Deep single-topic reference | Blog Page Kit ✓ |
| **Definition** | Explain one term the market keeps misusing | Blog Page Kit ✓ |
| **Listicle** | Fast scannable set of points | Blog Page Kit ✓ |
| **Steps** | A linear process laid out in order | Blog Page Kit ✓ |
| **Beginner guide** | Onboard a reader new to the category | Blog Page Kit ✓ |
| **Best practices** | Actionable recommendations from real work | Blog Page Kit ✓ |
| **Interview** | Borrowed authority plus genuinely unique content | nearest: Blog Page Kit |
| **Infographic page** | One idea carried visually | nearest: Blog Page Kit |
| **Press release** | An announcement built to be picked up and linked | no Kit |

## How to use the registry when planning a site

1. **Pick 2–4 pillar topics** tied to what the business actually sells. Everything else hangs off them.
2. **Cover the funnel per pillar.** Something top (definitions, lists, guides), something middle
   (comparisons, how-tos, checklists), something bottom (service page, cases, landing).
3. **One service page per service, then verticals underneath** — and only where the vertical passes
   the G-I gate in the Industry Page Kit.
4. **Every page links up and sideways.** Up to its parent, sideways to two siblings. A page with no
   inbound internal link is invisible to crawlers and to readers.
5. **Bottom-of-funnel pages carry the AI-visibility load**: comparison tables, FAQ schema, a visible
   updated date. Those are the elements AI search quotes back.

## What decides whether a page gets built at all

Ask these in order. A "no" ends the discussion for now.

- Does the query exist, or does the topic map to real pipeline?
- Is there proof to put on it — a case, a number, a working example?
- Is there something to say that no existing page on this site already says?
- Does it have a place in the blueprint, with a parent and a URL?

Volume without these produces a site full of pages that rank for nothing and answer no one.
