# Скіли маркетингу MobiDev для Claude Code

У цій гілці лежать скіли, якими користується команда. Зараз тут один скіл.

| Скіл | Що робить | Як запустити |
| --- | --- | --- |
| **site-content-audit** (плагін `content-audit`) | Аудит контенту сайту за одним посиланням: вичитка всіх сторінок, автоматичні перевірки, аудит schema (JSON-LD) для Google і AI-пошуку, Excel-звіт | Надіслати посилання і написати «зроби аудит контенту» |

Як працює аудит, детально описано в [METHODOLOGY.md](METHODOLOGY.md).

---

## Встановлення

Потрібен **Claude Code**: застосунок Claude на Mac/Windows, `claude` у терміналі або плагін для IDE.
У звичайному чаті claude.ai скіл повноцінно не запрацює (пояснення в розділі «Обмеження»).

### Спосіб 1. Як плагін (рекомендовано: оновлення приходять самі)

1. Переконайтеся, що маєте доступ на читання до репозиторію `mobidev-mrkt/landing` на GitHub
   і що git на вашому комп'ютері вже вміє його клонувати (SSH-ключ або `gh auth login` + `gh auth setup-git`).
2. У Claude Code виконайте:
   ```
   /plugin marketplace add mobidev-mrkt/landing#skills
   /plugin install content-audit@mobidev-skills
   ```
   Або одним рядком (Claude Code 2.1.275 і новіші):
   ```
   /plugin install content-audit --marketplace mobidev-mrkt/landing#skills
   ```
   Те саме з терміналу:
   ```bash
   claude plugin marketplace add mobidev-mrkt/landing#skills
   claude plugin install content-audit@mobidev-skills
   ```
3. Щоб підтягувати нові версії: `/plugin` → Marketplaces → `mobidev-skills` → увімкнути автооновлення,
   або вручну `claude plugin marketplace update mobidev-skills`.

Якщо SSH-ключа немає, перед командами задайте `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1`, і git піде через HTTPS.

### Спосіб 2. Скопіювати скіл собі (без плагіна)

```bash
git clone --branch skills --depth 1 git@github.com:mobidev-mrkt/landing.git mobidev-skills
mkdir -p ~/.claude/skills
cp -r mobidev-skills/plugins/content-audit/skills/site-content-audit ~/.claude/skills/
```
Скіл стане доступним у всіх ваших проєктах. Перезапускати Claude Code не треба; якщо скіл не з'явився,
виконайте `/reload-skills`. Оновлення в цьому разі робиться вручну: `git pull` і копіювання ще раз.

### Спосіб 3. Для всіх, хто працює з конкретним репозиторієм

Скопіюйте ту саму папку в `.claude/skills/site-content-audit/` потрібного репозиторію і закомітьте.
Скіл автоматично з'явиться в кожного, хто відкриє цей репозиторій у Claude Code.

### Залежності (один раз)

```bash
pip install openpyxl pyspellchecker
```
Також потрібні `python3` і `curl` (на Mac і Linux вони зазвичай уже є).

## Як користуватися

Напишіть у Claude Code, наприклад:

- `зроби аудит контенту https://mobidev.biz` → увесь сайт за sitemap.xml
- `зроби аудит контенту https://mobidev.biz/blog` → лише блог
- `вичитай https://mobidev.biz/case-studies/apple-watch-multisport-companion` → одна сторінка
- `перевір schema на https://mobidev.biz/services/` → розділ, разом зі schema-аудитом

Claude сам визначить обсяг за посиланням, скаже, скільки сторінок буде перевірено, і повідомлятиме
про прогрес. Якщо сторінок понад ~400, він один раз спитає, чи включати блог.

**Результат:** Excel-файл із вкладками

| Вкладка | Що там |
| --- | --- |
| Зведення | Підсумки за типами й пріоритетами |
| Знахідки (сайт) / Знахідки (блог) | Описки, граматика, плейсхолдери, зламаний текст, нестиковки, застаріле, title/meta. Кожен рядок: сторінка, точна цитата для Ctrl+F, як виправити, пріоритет, статус |
| Факти компанії | Факти про компанію, що різняться між сторінками (вік, кількість клієнтів, рейтинги…) |
| Title і meta | Порожні, задовгі й дубльовані title та description, кількість H1 |
| Schema — весь сайт | Проблеми розмітки, спільні для всього сайту: Organization, рейтинги, llms.txt, robots.txt |
| Schema — по сторінках | Чого бракує кожній сторінці для Google і AI-пошуку |
| Schema — шаблони | Готові JSON-LD для кейсу, статті, сторінки експерта, сервісу, Organization, відео |

Колонка «Статус» має випадний список: Не почато / В роботі / Виправлено / Не баг.

## Обмеження

- **Тривалість і ліміти.** Повний аудит великого сайту триває від 15 хвилин до години і запускає
  десятки агентів, тобто суттєво витрачає ліміт використання. Почніть з розділу, якщо сумніваєтеся.
- **Доступ до сайту.** Сесія має бачити сайт. У хмарній сесії (claude.ai/code) домен сайту потрібно
  дозволити в мережевих налаштуваннях середовища.
- **Скіли, встановлені на комп'ютері (способи 2 і 3), у хмарних сесіях не підхоплюються.** Там
  використовуйте плагін або скіл у самому репозиторії, з яким працює сесія.
- **claude.ai (звичайний чат).** Завантажити туди скіл zip-архівом можна (Customize → Skills), але
  в цьому середовищі за замовчуванням немає доступу до довільних сайтів і паралельних агентів, тому
  повний аудит там не відпрацює.
- **Що аудит не перевіряє:** зображення й вигляд сторінок, валідацію через Google Rich Results Test.
  Колонка «Як виправити» подекуди лише пропозиція. Якщо там названо факт (рік, кількість), його треба підтвердити.
- **Сайт аудит не змінює.** Лише звіт.
